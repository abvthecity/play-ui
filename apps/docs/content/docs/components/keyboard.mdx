Point at a shortcut, or search for one, and the board lights the keys it presses. Type in the search
field and the keys light as they go down. Switch the layout or the platform and the same shortcut
lands on different caps: `@` is shift and 2 on a US board but shift and the quote on a British PC,
and `Mod+K` is ⌘K on a Mac but ctrl K on a PC.

The package owns the board as data, which caps a shortcut presses, and the state for a searchable
sheet of shortcuts, with no dependencies of its own. Shortcuts are hotkey strings in the form
[TanStack Hotkeys](https://tanstack.com/hotkeys/latest) uses (`"Mod+K"`), so the string that binds a
shortcut there lights it here. What any of it looks like is yours.

## Anatomy

```tsx
import { Keyboard, createBoard, mac, qwertyUS, triggerOf } from "@play-ui/react-keyboard";

const board = createBoard(qwertyUS, mac);

<Keyboard board={board} trigger={triggerOf(board, "Mod+K")} className="keyboard" />;
```

A board is a **layout** drawn for a **platform**. Both are plugins: plain objects, each in its own
module, so your bundle keeps only the ones you import. A site that only ever draws a US Mac board
ships neither the British nor the international layout, nor the PC platform.

## Layouts

A layout owns the four rows of characters: where the keys are and what each one types, with and
without shift.

| Export                | Shape | Description                                                                                              |
| --------------------- | ----- | -------------------------------------------------------------------------------------------------------- |
| `qwertyUS`            | ANSI  | The US board: a one-row return and a long left shift.                                                    |
| `qwertyUK`            | ISO   | The British board: a tall return, `£` over 3 and an extra key before Z. A Mac and a PC differ in places. |
| `qwertyInternational` | ISO   | The US symbols on the ISO shape, as English keyboards are sold across Europe.                            |

## Platforms

A platform owns the machine around the characters: the function row, the modifier row, the words
printed on the named keys, and which platform its hotkeys are read for (`platform.hotkeys`).

| Export | Description                                                                                                                      |
| ------ | -------------------------------------------------------------------------------------------------------------------------------- |
| `mac`  | A Mac laptop: blank function keys, then fn, control, option and command. Prints `delete` and `return`. `Mod` holds command.      |
| `pc`   | A Windows or Linux laptop: printed F-keys, then ctrl, fn, the Windows key and alt. `Mod` holds ctrl, and `Meta` the Windows key. |

On a British or international PC, the right alt is alt gr: it types accents rather than holding alt,
so an `Alt` shortcut lights only the left one.

To pick a platform for the reader, test `navigator.userAgent` (or `navigator.userAgentData.platform`)
after mount, and fall back to one when rendering on the server.

## Triggers

A trigger is what a shortcut presses on a board. A string is a chord, held together; a `sequence`
is typed one key after the other; and `any` is any one of a run.

```ts
triggerOf(board, "Mod+K"); // a chord: held together
triggerOf(board, { sequence: ["G", "I"] }); // typed one after the other
triggerOf(board, { any: ["1", "2", "3", "4", "5", "6"] }); // any one of a run
```

Each hotkey is read for the board's platform: `Mod` holds command on a Mac and ctrl on a PC. The
package reads the same strings TanStack Hotkeys does: its modifier and key aliases (`Cmd`, `Option`,
`esc`, `return`), a physical key by code in brackets (`[KeyK]`), and `Mod++` for plus. It also reads
the glyphs a Mac prints (`⌘`, `⇧`, `↵`). `parseHotkey(hotkey, platform)` takes one apart.

- A modifier lights every cap that holds it: `Shift` lights both shifts.
- A character typed with shift brings shift along, wherever the layout puts it: `?` is shift and `/`.
- `Home`, `End`, `PageUp` and `PageDown` are fn with an arrow, and `Delete` is fn with backspace, as
  on a laptop.
- Hotkeys whose key the board has no cap for are listed in `trigger.unknown`.

Each cap's id is the `KeyboardEvent.code` of the key at that spot, so real key presses light the
board too. `chordOf(codes)` turns the codes held right now into a trigger:

```tsx
const [held, setHeld] = useState(new Set<string>());

<input
  onKeyDown={(event) => setHeld((keys) => new Set(keys).add(event.code))}
  onKeyUp={() => setHeld(new Set())}
/>
<Keyboard board={board} trigger={held.size > 0 ? chordOf(held) : null} />;
```

## Shortcut sheet

`useShortcutSheet(groups, { platform })` holds the state for a searchable list of shortcuts: the query, the groups
it leaves, and the active row. The active row is the one pointed at, or arrowed to from the search
field, or the first result while there is a query. Light the board from it:

```tsx
const groups = [
  {
    id: "around",
    title: "Get around",
    items: [
      { id: "palette", label: "Search and commands", hotkey: "Mod+K" },
      { id: "inbox", label: "Go to the inbox", hotkey: { sequence: ["G", "I"] } },
    ],
  },
];

const sheet = useShortcutSheet(groups, { platform: board.hotkeys });
const trigger = sheet.active ? triggerOf(board, sheet.active.hotkey) : null;

<input
  value={sheet.query}
  onChange={(event) => sheet.setQuery(event.target.value)}
  onKeyDown={sheet.onInputKeyDown}
/>
<ul ref={sheet.attachList}>
  {sheet.results.flatMap((group) =>
    group.items.map((item) => (
      <li key={item.id} data-shortcut-id={item.id} onPointerEnter={() => sheet.point(item.id)}>
        {item.label}
        {hotkeysOf(item.hotkey).map((hotkey) => (
          <kbd key={hotkey}>{hotkey}</kbd>
        ))}
      </li>
    )),
  )}
</ul>
<Keyboard board={board} trigger={trigger} />;
```

`hotkeysOf(binding)` lists the hotkeys a chord, sequence or run is made of.

Every word of a query must land in a label, a group's title or on a key. A key word is read as a
hotkey is for the platform, so `cmd k` finds `Mod+K` on a Mac and `ctrl k` finds it on a PC, and a
glyph (`⌘`, `↵`) lands too. `searchShortcuts(groups, query, platform)` is the same search as a pure
function.

## Using with TanStack Hotkeys

The package listens for nothing, so pair it with a hotkey library that does. With
[TanStack Hotkeys](https://tanstack.com/hotkeys/latest), keep one list of shortcuts and hand the
same strings to both: TanStack binds them, the board lights them, and they never drift apart. The
demo above is built this way.

```tsx
import {
  formatForDisplay,
  useHeldKeyCodes,
  useHotkey,
  useHotkeySequence,
} from "@tanstack/react-hotkeys";
import { chordOf, hotkeysOf, triggerOf } from "@play-ui/react-keyboard";

const palette = "Mod+K";
const inbox = ["G", "I"];

// TanStack binds the shortcuts…
useHotkey(palette, openPalette);
useHotkeySequence(inbox, openInbox);

// …and the board lights the same strings.
triggerOf(board, palette);
triggerOf(board, { sequence: inbox });

// Light the keys held right now. TanStack lets go of the ones a Mac never sends a key-up for while
// command is down.
const held = Object.values(useHeldKeyCodes());
<Keyboard board={board} trigger={held.length > 0 ? chordOf(held) : null} />;

// Print each hotkey as the platform does: ⌘ K on a Mac, Ctrl+K on a PC.
hotkeysOf(item.hotkey).map((hotkey) => formatForDisplay(hotkey, { platform: board.hotkeys }));
```

A platform's `hotkeys` field is named as TanStack names its platforms (`"mac"`, `"windows"`,
`"linux"`), so it passes straight to TanStack's `platform` options.

## Styling

Every row of a board adds up to the same 14.5 units, so the drawing is a stack of flex rows with
`flex-grow` set to each cap's width:

```css
.keyboard [data-part="row"] {
  display: flex;
  gap: 6px;
  height: 44px;
}

.keyboard [data-part="cap"],
.keyboard [data-part="stack"] {
  flex: var(--cap-width) 1 0;
}

.keyboard [data-part="cap"][data-lit] {
  background: orange;
}
```

For a cap with depth, a band as tall as `--cap-depth` along its bottom edge, pad the cap's bottom by
the same amount so its legend centres on the face above the band, half the depth higher:

```css
.keyboard {
  --cap-depth: 2px;
}

.keyboard [data-part="cap"] {
  padding-bottom: var(--cap-depth);
  box-shadow: inset 0 calc(var(--cap-depth) * -1) 0 rgb(0 0 0 / 0.06);
}
```

The ISO return spans two rows. It is one `data-part="cap"` in the upper row, and a
`data-part="foot"` that holds its room in the row below (give it the same `flex` as a cap). The cap
draws its L-shaped outline as an `svg[data-part="shape"]`, with the corners of the cap's own
`border-radius`, and carries `data-shaped` once it is drawn. Its three paths take the layers a box
would: `shape-face` is the fill, `shape-edge` is a stroke clipped to the inside of the L (so a 2px
stroke is a 1px inset edge), and `shape-depth` is the band along every bottom edge, as tall as the
cap's `--cap-depth`. Give them the same colours as your caps and the return matches them exactly:

```css
.keyboard {
  --cap-depth: 2px;
}

.keyboard [data-part="foot"] {
  flex: var(--cap-width) 1 0;
}

.keyboard [data-part="cap"][data-shaped] {
  overflow: visible;
  background: none;
  box-shadow: none;
}

.keyboard [data-part="shape-face"] {
  fill: rgb(0 0 0 / 0.04);
}

.keyboard [data-part="shape-edge"] {
  stroke: rgb(0 0 0 / 0.1);
  stroke-width: 2px;
}

.keyboard [data-part="shape-depth"] {
  fill: rgb(0 0 0 / 0.06);
}
```

## Accessibility

The board is a picture of the keys a shortcut presses, never a control, so it is `aria-hidden`. The
row it illustrates already says the same thing in words and key caps; keep that text in your sheet.

## API reference

### Keyboard

Renders a `div` of rows. Accepts `className` (a string, or a function of the state) and `render`.

| Prop      | Type              | Description                                   |
| --------- | ----------------- | --------------------------------------------- |
| `board`   | `Board`           | The board to draw, from `createBoard`.        |
| `trigger` | `Trigger \| null` | What to light, or `null` for a board at rest. |

| Attribute / variable          | Description                                                                                                        |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `data-layout`                 | The layout's id, on the root.                                                                                      |
| `data-platform`               | The platform's id, on the root.                                                                                    |
| `data-kind`                   | `"chord"`, `"sequence"` or `"any"` while something is lit.                                                         |
| `data-part`                   | `"row"`, `"stack"` (↑ over ↓), `"cap"`, `"foot"`, and inside a cap `"legend"`, `"shifted"`, `"sub"` and `"shape"`. |
| `data-key`                    | A cap's `KeyboardEvent.code`.                                                                                      |
| `data-lit`                    | Present on a lit cap.                                                                                              |
| `data-step`                   | A sequence's 1, 2, … on its lit caps.                                                                              |
| `data-half` / `data-blank`    | The short caps and the empty ones.                                                                                 |
| `data-modifier`               | `"shift"`, `"control"`, `"alt"` or `"meta"` on a modifier.                                                         |
| `data-span` / `data-shaped`   | `"upper"` on a cap spanning two rows; `data-shaped` once its outline is drawn.                                     |
| `--cap-width` / `--cap-index` | A cap's width in key units, and its place on the board.                                                            |

### createBoard

`createBoard(layout, platform)` returns a `Board`: `{ layout, platform, hotkeys, rows, keys,
modifiers }`. `keys` maps every key the board has, by key name (`K`, `Enter`, `?`) and by
code in brackets (`[KeyK]`), to the caps it presses; `modifiers` lists the caps holding each
modifier.

### triggerOf

`triggerOf(board, binding)` returns `{ kind, steps, unknown }`, where a binding is a hotkey string,
`{ sequence }` or `{ any }`. `capsForHotkey(board, hotkey)` is the same lookup for one hotkey, and
`litCaps(trigger)` maps each lit cap to its step.

### Your own layout or platform

A layout is `{ id, name, rows(platform), overrides? }`, where `rows` returns the four rows of
characters for a platform id. A platform is `{ id, name, functionRow, modifierRow, legends, hotkeys }`,
where `hotkeys` is `"mac"`, `"windows"` or `"linux"`, the platform `Mod` is resolved for.
Build their caps with `cap`, `charCap` and `letterCaps`, and keep every row at 14.5 units
(`rowWidth` adds one up).
